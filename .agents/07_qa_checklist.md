# 07 — QA Checklist Before Finishing a Task

Run **both QA layers first**.

Deterministic gate:
```bash
python3 .agents/tools/qa_automation.py \
  --folder data/[video_long|video_short]/[title-slug] \
  --lang <vi|en>
```
This hard-checks schema closure/no extra fields, scene numbering, word counts,
subtitle integrity, non-resetting `sentence_id`, exact `part=x/N` progression,
SHORT/LONG aspect ratio, named canonical visual-bible anchors, the complete
Negative list, continuity-format rules, prompt language/audio/single-shot
constraints, the 900–4,000 total-character production range plus >=800 positive visual characters before Negative, global film-look reuse, duplicate-anchor prevention, and core cinematography detail contract.

AI-assisted semantic editor gate:
```bash
python3 .agents/tools/scene_semantic_checker.py \
  --folder data/[video_long|video_short]/[title-slug] \
  --ai-model <agy|codex>
```
This specifically reviews scene↔voiceover fidelity, `context_ref` use,
multi-part progression, semantic identity drift, continuity and physical
plausibility. Exit code 3 means the AI review did **not** run; it is not a
PASS, so perform those semantic items manually.

Neither layer removes the need for final human/agent judgment on ambiguous
style, factual-mode, policy, lighting/weather, and documentary-editorial
choices.

Complete the full list below before updating `database/history.json` (Step
11 in `01_workflow.md`). If any item FAILS → go back to the relevant step
and fix it; never skip an item.

## A. Data & Schema

- [ ] `master_script.txt` is within the character-length policy for its
      `videoType` (900–1,200 for short; LONG must be **>60,000 Unicode characters**, recommended **65,000+**, with no maximum, and must still pass completeness/anti-padding quality gates)
- [ ] Every JSON file (`metadata.json`, `visual_bible.json`, every
      `chapter_0X.json`) passes `tools/schema_validator.py`
- [ ] Every `voiceover`/`sub` was generated by `tools/word_splitter.py` at
      the exact required word count — no scene exceeds the allowed word count
- [ ] `scene` in every chapter file increases sequentially, with no
      duplicates and no gaps
- [ ] For a multi-chapter Long video: `sentence_id` is carried correctly
      across chapter files (`--scene-start`/`--sentence-start` were used
      when calling `word_splitter.py`; no chapter's `sentence_id` resets
      back to 1 partway through)
- [ ] `part` for scenes sharing a `sentence_id` is sequential and in the
      right order among the parts **actually assigned** to that
      `sentence_id` (note: some very short sentences may not get their own
      `sentence_id` — this is known, documented behavior, see
      `04_scene_splitting_rules.md §6`, not a bug)
- [ ] `context_ref` has not leaked into `sub`, `metadata.json`, or any other
      viewer-facing output
- [ ] `visual_bible.json` has the required `story_anchor` (2–4 sentences on the whole
      video's throughline) — required in practice for every Long video with
      2+ chapters

## B. Visual Consistency

- [ ] Every character appearing more than once has an **identical**
      description across every `veo_prompt` (cross-check against
      `visual_bible.characters`)
- [ ] Every recurring location has a consistent description (cross-check
      against `visual_bible.locations`)
- [ ] The lighting/time-of-day progression between scenes matches
      `lighting_timeline`, with no illogical jumps (unless the script
      intentionally time-skips, and that is clearly reflected in
      `continuity_ref`)
- [ ] Every `veo_prompt` lists `negative_keywords`
- [ ] Spot-check a sample of scenes (at minimum the first/last scene of each
      chapter and every scene in at least one multi-part `sentence_id`): does
      the `veo_prompt` depict the **current `voiceover` beat**, interpreted
      correctly through `context_ref`, and progress according to `part`? It
      must not repeat the same whole-sentence visual in every part, reveal a
      later clause early, or drift into a nice but narration-irrelevant shot
      (see `06_veo_prompt_guide.md §1`).

- [ ] **Semantic Lock passes for every scene:** the primary visible subject/action is justified by the CURRENT `voiceover`; `context_ref` only resolves meaning; `continuity_ref` carries previous state only and never introduces a later claim, opposing argument, later location, or future `part`.
- [ ] Epistemic status matches narration: possibilities/hypotheses/preliminary evidence are shown as conceptual/simulated/uncertain, never as confirmed reality.
- [ ] **Material fidelity contract satisfied:** every scene with physical materials includes at least one physically grounded rendering descriptor from `02_content_style.md §5.0` (skin subsurface scattering, fabric drape, weathered stone, timber grain, natural water/fire/smoke behavior; never plastic/waxy/flat/game-engine CGI per `06_veo_prompt_core.md §11`).
- [ ] Color grading aligns with the scene-type palettes in `references/color_palette_system.md` (Palettes A–G) rather than mechanically defaulting to universal warm amber across night, rain, or forest scenes.
- [ ] Every `veo_prompt` includes `visual_style.film_look` verbatim **exactly once**, plus a concrete lens/focus choice, motivated lighting, useful physical/environmental behavior, and one continuous micro-action ending in a clear final visual state.
- [ ] No canonical character/location/key-object description is pasted more than once in the same prompt.
- [ ] No two non-identical scenes reuse an exactly identical `veo_prompt`.
- [ ] Veo is not asked to generate exact readable captions, formulas, dates, labels, long UI copy, or statistics; use text-free/unlabeled visualizations and add exact typography in post-production.

## C. Continuity

- [ ] Every scene (except scene 1 of `chapter_01.json`) has a
      `continuity_ref` matching the previous shot's end state/editorial
      handoff across the whole video, including chapter boundaries. For
      continuous action, preserve subject/object state, screen direction,
      pose/gaze, weather and light. For a narration-driven location/time/
      concept change, the jump must be intentional rather than an accidental
      reset. Never leave it blank, and never use `"opening"` after scene 1.
- [ ] No two consecutive scenes mechanically/boringly reuse the same
      `shot_type`, unless clearly intentional
- [ ] Camera movement follows anti-repetition rules in `references/camera_variety_guide.md` (no identical movements in consecutive scenes; max 2 slow dolly push-ins per 6-scene batch; at least 3 distinct movements per batch)
- [ ] Scenes sharing a `sentence_id` (one sentence split across multiple
      parts) show different angles/moments, not a repeated frame
- [ ] No `veo_prompt` contains transition/multi-shot language ("then,"
      "cuts to," "transitions to," "fades to," "morphs into," etc.) — each
      `veo_prompt` is one single continuous shot, per
      `06_veo_prompt_guide.md §2.4`
- [ ] Every `veo_prompt` describes a single beat that plausibly fits in
      4/6/8 seconds — no scene packs in more than one distinct action (see
      `06_veo_prompt_guide.md §0` rule 4 and `§6`)
- [ ] Dynamic elements are physically coherent where relevant: gravity/
      inertia, contact, travel direction, wind/rain/water/particles, shadows,
      reflections, scale, and cause→effect do not reset or contradict the
      previous scene/phenomenon without narration support.
- [ ] Across adjacent clips, camera/subject screen direction and visual
      anchors are intentionally preserved or intentionally changed; shot
      variety is not achieved by random axis flips that make the edit feel
      discontinuous.

## D. Content & Style

- [ ] `voiceStyle` is applied correctly and consistently throughout
      `master_script.txt` (see `02_content_style.md`)
- [ ] For `mode = "1"` (Chiêm nghiệm / Contemplative reflection): the line between established canonical teaching and personal reflection/modern application is clear, never blurred together (see `references/buddhist_glossary.md`)
- [ ] For `mode = "2"` (Kiến thức / Canonical & Historical knowledge): base claims on canonical texts, historical records, or verified research; sutra references and historical facts must be accurately attributed (see `references/canonical_texts_reference.md`)
- [ ] `main_video_content` does not duplicate a previous video's content in
      `history.json` (applies when `generationMethod = auto`)
- [ ] For auto generation, `data/.agent_runtime/_topic_research.json` passed `topic_research_gate.py --verify-sources --verify-content`: 8–12 real candidate angles were compared using current evidence; selected sources were public-network safe, reachable, freshness-consistent, and their retrieved content substantiated the selected angle/support notes. `_topic_evidence_content_receipt.json` matches the current research ledger.
- [ ] The master script has a clear promise → evidence/escalation → payoff
      arc; chapters are not just loosely related facts, and the ending
      resolves the opening question to the level the evidence permits.
- [ ] `data/.agent_runtime/_editorial_message_lock.json` passed
      `tools/editorial_script_gate.py` both before prose and against the final
      `master_script.txt`; it contains one central question, one core message,
      viewer value, key revelations, epistemic boundary, and ending takeaway.
- [ ] The final script also passed `tools/editorial_semantic_checker.py`; `_editorial_semantic_receipt.json` is hash-current for the exact Editorial Message Lock + `master_script.txt`, so final QA verifies the receipt instead of spending a duplicate whole-script AI pass.
- [ ] A listener without the images can follow the complete main idea: major
      reveals supply the needed WHAT → HOW/WHY → HOW WE KNOW → WHY IT MATTERS
      links rather than jumping between impressive facts.
- [ ] Spoken cadence is natural: sentences generally carry one job; repeated
      45–60+ word sentence chains have been split/reworked without losing
      meaning; technical terms are explained when first needed.
- [ ] Hype density is controlled: facts/mechanisms create the wonder; the same
      dramatic adjective/phrase is not recycled, and narration does not become
      trailer copy.
- [ ] Claim strength is audible and accurate: proposal/model ≠ proof,
      association ≠ causation, preliminary ≠ established, and a plausible
      explanation is not narrated as a fully solved mechanism.
- [ ] The ending synthesizes the story and leaves the declared `core_message`
      in fresh wording; it does not introduce a large unrelated branch or end
      on an empty engagement question.
- [ ] Hooks and narration do not invent precise dates, measurements,
      countdowns, probabilities, quotes, causal claims, or superlatives for
      drama.
- [ ] The script passes the visual-translatability gate in
      `02_content_style.md §8`; long abstract stretches have been rewritten
      before scene splitting rather than patched with unrelated B-roll.

## E. VEO 3.1 / Flow Content-Policy Compliance

Full detail and rationale: `12_veo_policy_compliance.md`. Run through this
for every `veo_prompt` before considering the task done:

- [ ] No `veo_prompt` depicts a real, named, identifiable person by their
      actual likeness — every human `visual_bible.characters` entry is
      generic/anonymized, even for scenes referencing a real person named
      in `master_script.txt`
- [ ] No copyrighted character, logo, or recognizable branded design
      appears in any `veo_prompt`
- [ ] Any disaster/catastrophe/violence content stays at
      environmental/scale level — no injury, gore, or casualty detail
- [ ] Any speculative/hypothesis scene (`mode = "1"`) is explicitly framed
      as simulated/conceptual in the `veo_prompt` wording itself, not just
      in the narration
- [ ] No sexual, suggestive, hateful, or self-harm content in any prompt
- [ ] Every `veo_prompt`'s `Negative:` clause includes the policy-safety
      keywords from `12_veo_policy_compliance.md §4`, in addition to the
      visual-quality keywords

## F1. Format — Language & Audio (`06_veo_prompt_guide.md §0`)

- [ ] Every `veo_prompt` is written **entirely in English**, even for
      `language: vi` videos — no Vietnamese text anywhere inside a
      `veo_prompt` (only `context_ref`/`voiceover`/`sub` may be Vietnamese)
- [ ] No `veo_prompt` contains any mention of audio/sound/dialogue in
      either direction — no `Audio:` clause, no "silent"/"no dialogue"/"no
      music"/"no sound effects," and no description of a character
      speaking/singing/shouting as a sound event. This project intentionally
      keeps `veo_prompt` visual-only because narration/TTS is mixed separately
      (`06_veo_prompt_guide.md §0 rule 2`) — a prompt that still carries an
      old silent-audio directive is a format violation, not a harmless leftover
- [ ] Every `veo_prompt` is **900–4,000 Unicode characters total (including `Negative:`), with at least 800 positive visual characters before `Negative:`**. The floor prevents under-specified scene briefs; prompts are never padded with filler,
      and over-limit drafts are compressed by removing redundancy rather than
      deleting essential scene/identity/continuity/safety information
      (`06_veo_prompt_guide.md §7`).

## F2. Cinematic Variety & Anti-Drift (`06_veo_prompt_guide.md §0.5`, `§2.9`)

- [ ] Camera framing/angle/movement/lens choices are varied deliberately
      across the video, drawing on the full vocabulary in
      `06_veo_prompt_guide.md §2.9` — not mechanically defaulting to the
      same 2–3 shot types throughout
- [ ] Each prompt normally has one primary framing, one angle, one movement,
      and one lens/focus strategy; cinematic vocabulary is not stacked into
      conflicting instructions simply to sound sophisticated.
- [ ] Scenes sharing one `sentence_id` create a visual progression across
      `part` values (setup → development → detail/payoff as appropriate), not
      cosmetic camera changes over an otherwise identical frame.
- [ ] For a multi-chapter Long video: spot-check that character/location
      wording in chapter 4+ still matches `visual_bible.json` verbatim,
      confirming the anti-drift protocol (`06_veo_prompt_guide.md §0.5`)
      was actually followed and no slow drift crept in over the job

## F3. Cleanup & File Management

- [ ] All temporary files created during processing have been deleted:
      - `data/.agent_runtime/_chapter_*_raw.txt` (if multi-chapter Long video)
      - `data/.agent_runtime/_topic_research.json` (after the successful history entry is appended)
      - `data/.agent_runtime/_editorial_message_lock.json` (after the successful history entry is appended)
      - `data/.agent_runtime/_claim_evidence.json` and `_claim_evidence_content_receipt.json` when used (after successful final QA/history append)
      - `_topic_evidence_content_receipt.json` and `_source_verification_cache.json` after successful history append when no longer needed
      - `_veo_progress_<slug>.json` / `_veo_semantic_receipts_<slug>.json` after final QA + history completion
      - Any other intermediate/debug files not in the final output structure
- [ ] Only final output files remain in `data/[video_long|video_short]/[title-slug]/`:
      - `master_script.txt`
      - `metadata.json`
      - `visual_bible.json`
      - `chapter_01.json` ... `chapter_[n].json`


## F4. Long-job stamina / anti-laziness checkpoint

- [ ] Scenes were written in contiguous batches of 6 by default and never more than 8 before a checkpoint.
- [ ] Every completed batch passed `tools/veo_batch_guard.py --checkpoint` before the next batch was written.
- [ ] Every batch also passed `scene_semantic_checker.py --scene-start ... --scene-end ...`; exit 3 was never treated as PASS.
- [ ] If the agent/context was interrupted or became long, work resumed from `data/.agent_runtime/_veo_progress_<slug>.json` after re-reading `visual_bible.json`, the previous 2 scenes, and the current narration — never from memory.
- [ ] `_veo_semantic_receipts_<slug>.json` was retained through final QA and deleted only after successful final QA + history completion.
- [ ] Prompt detail, style-anchor use, identity specificity, and semantic fidelity remain equally strong in the final 20% of scenes as in the first 20%; no late-job shortening/template reuse is accepted.

## F5. GenerateVeoPrompts full-regeneration integrity

- [ ] Every GenerateVeoPrompts run/rerun began with `tools/veo_regeneration_prepare.py`; no prior six-field Veo package was trusted.
- [ ] `context_ref`, `sentence_id`, and `part` were rebuilt by the canonical splitter rather than edited by hand/LLM inference.
- [ ] Old `continuity_ref`, `shot_type`, and `veo_prompt` were invalidated and regenerated from Scene 1.
- [ ] Old `_veo_progress_<slug>.json`, `_veo_semantic_receipts_<slug>.json`, and `all_veo_prompt.json` were not reused.
- [ ] Final `qa_automation.py` passed its independent canonical alignment re-derivation check.
## G. Production-v3 gates added after real-output audit

- [ ] Positive visual body (before `Negative:`) is at least 800 characters of useful, non-redundant direction; Negative boilerplate does not count.
- [ ] Each scene starts and remains in one visual domain; no hidden `drone → cross-section`, `lab → molecule`, `landscape → diagram` transformation.
- [ ] Camera rig vocabulary matches scale/domain: no crane/dolly kilometers, no drone inside matter, no physical lens traveling through solid geology.
- [ ] `continuity_ref` for scene >1 contains `Previous end:` + `Current opening:` (+ required `Editorial relationship:`) and describes endpoints rather than asking the clip to transition between them.
- [ ] Positive prompt does not request anything forbidden by its own Negative clause; exact readable logos/emblems/certificates/plaque wording/formulas/numbers are deferred to post.
- [ ] Evidence visualization does not become a verdict: absence of detected evidence is scoped; hypotheses/reconstructions remain qualified.
- [ ] Any alias of a recurring visual-bible entity still triggers its canonical anchor; visually different eras/outfits are separate identity entries.
- [ ] When Claim Evidence Lock applies, the pre-script production gate passed with `--verify-sources --verify-content --ai-model <queue.aiModel>` and wrote `_claim_evidence_content_receipt.json`; the post-script `--script --require-content-receipt` pass confirms that receipt still matches the exact ledger hash. Named institutions, numbers, dates, causation and historical claims are covered and use no stronger wording/visual than allowed.

- [ ] If any scene contains `timeline`, all scenes contain timeline data and final QA confirms contiguous boundaries, `duration=end-start`, formatted timestamps, and valid speed.
- [ ] `negative_keywords` contains the complete mandatory safety baseline and current V9 no-edit baseline; prompts copy the required lock exactly.

## H. V9 zero-tolerance scene locks

- [ ] Every `veo_prompt` starts exactly with `Create exactly one uninterrupted continuous shot in one visual setup for the entire clip.`
- [ ] Every `Negative:` contains exactly the no-internal-edit lock `internal cuts, scene transitions, fades, dissolves, morph transitions, montage, time jumps, location changes, visual-domain changes`.
- [ ] Positive prompt text contains no internal edit/sequencing instruction: no cut/fade/dissolve/crossfade/wipe/morph/montage/split-screen/flashback/time jump/location jump/domain change/second shot; no `then`/`next`/`followed by` construction scheduling another beat.
- [ ] Named Subject Lock passes: the current `voiceover` subject is the hero subject; no same-category substitution.
- [ ] Future Subject Lock passes: nothing first introduced by a later scene appears early, including visually identifiable teasers.
- [ ] Natural motion, ritual actions, human gestures, fire/water/smoke, weather, and historical reconstruction remain physically plausible at clip time scale; no invented event is smuggled in through visual dramatization.
- [ ] No prompt asks Veo to render a large exact count of repeated objects; exact numbers/counts are added in post.
- [ ] Every deterministic micro-batch has a current hash-matching semantic PASS receipt generated by `scene_semantic_checker.py`.
- [ ] Final `qa_automation.py` reports full semantic receipt coverage; no missing/stale receipt is waived.
- [ ] Exit 3/unavailable AI semantic review is never accepted as PASS.
