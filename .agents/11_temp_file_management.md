# 11 — Temporary File Management & Cleanup

## Purpose

This guide ensures agents keep the workspace clean by properly managing
temporary files created during video processing. Following these rules
prevents clutter in the source code and makes the project maintainable.

---

## 1. Designated Temporary Directory

**All temporary files MUST be created in:**
```
data/.agent_runtime/
```

**Never create temporary files in:**
- `data/video_short/[title-slug]/` (final output only)
- `data/video_long/[title-slug]/` (final output only)
- Project root
- `.agents/` folder

---

## 2. Types of Temporary Files

### A. Chapter extraction files (Long videos only)

**File pattern:** `_chapter_01_raw.txt`, `_chapter_02_raw.txt`, etc.

**Purpose:** Store extracted text for each chapter when splitting
`master_script.txt` for multi-chapter Long videos.

**Location:** `data/.agent_runtime/_chapter_XX_raw.txt`

**Lifecycle:**
1. Create when extracting chapter text in Step 7 (workflow)
2. Use as input to `word_splitter.py`
3. Delete after all chapters processed and validated (before Step 9)

### B. AI semantic checker temporary files

**File pattern:** Auto-generated by `tempfile.NamedTemporaryFile`

**Purpose:** Pass prompts to agy CLI in `ai_semantic_checker.py`

**Location:** System temp directory (OS-managed)

**Lifecycle:** Automatically cleaned up by the tool after use (already implemented)

### C. Auto-topic research evidence ledger (auto mode only)

**File:** `_topic_research.json`

**Purpose:** Runtime-only evidence record for the 8–12 topic candidates used
in Step 2, including freshness/momentum, source URLs/dates, visual richness,
novelty and the selected angle. It makes the "hot topic" decision auditable
without changing any final video-output schema.

**Location:** `data/.agent_runtime/_topic_research.json`

**Lifecycle:**
1. Create during auto-topic research in Step 2
2. Validate against `schemas/topic_research.schema.json`
3. Pass `tools/topic_research_gate.py`
4. Keep it available through final QA if the topic decision needs review
5. Delete after the successful history entry is appended in Step 11


### D. Source verification/content-support runtime artifacts

**Files:** `_source_verification_cache.json`, `_topic_evidence_content_receipt.json`, `_claim_evidence.json`, `_claim_evidence_content_receipt.json`

**Purpose:** Cache safe URL reachability and prove that retrieved source content supports the exact topic/claim ledger version without adding any final-output field. Content receipts are hash-bound to their ledger.

**Lifecycle:**
1. Create during Step 2 production evidence verification.
2. Keep `_claim_evidence.json` + `_claim_evidence_content_receipt.json` through final QA.
3. Recreate the content receipt whenever its source ledger changes.
4. Delete after successful final QA + history append.
5. Never copy these files into a final video folder.

### E. Editorial Message Lock (all script-generation tasks)

**File:** `_editorial_message_lock.json`

**Purpose:** Runtime-only central-question/core-message plan used inside Step 3
to keep narration complete, natural, and message-focused without adding fields
to final project JSON.

**Location:** `data/.agent_runtime/_editorial_message_lock.json`

**Lifecycle:**
1. Create before final prose in Step 3.
2. Validate against `schemas/editorial_message_lock.schema.json`.
3. Pass `tools/editorial_script_gate.py` preflight and final-script pass.
4. Keep through final QA if editorial review is needed.
5. Delete after successful history append in Step 11.

### F. Veo scene progress checkpoint (scene-heavy jobs)

**File pattern:** `_veo_progress_<slug>.json`

**Purpose:** Runtime-only resumable checkpoint written by `tools/veo_batch_guard.py`. It records the last batch that passed the deterministic scene gate plus source-file hashes. This prevents a long-running agent from losing its place, skipping scenes, or continuing from memory after context fatigue/interruption.

**Location:** `data/.agent_runtime/_veo_progress_<slug>.json`

**Lifecycle:**
1. Created/updated after each successful 6-scene (max 8) prompt batch with `--checkpoint`.
2. Read before resuming an interrupted/long job.
3. If `master_script.txt` or `visual_bible.json` changes intentionally after prompting begins, reset the checkpoint and re-guard from scene 1 (`veo_batch_guard.py --reset-checkpoint`).
4. A full `GenerateVeoPrompts` rerun is also a hard invalidation event: `veo_regeneration_prepare.py` deletes this checkpoint before regenerating from Scene 1; never resume a new prompt run from an old checkpoint.
5. Kept until full deterministic + semantic final QA passes.
6. Deleted after the successful history entry is appended in Step 11.

### G. Validation working files

**File pattern:** `_temp_history_entry.json`, `_validation_*.json`

**Purpose:** Test single history entries against schema before appending to
`database/history.json`

**Location:** `data/.agent_runtime/_temp_*.json`

**Lifecycle:**
1. Create when preparing history entry validation
2. Validate with `schema_validator.py`
3. Delete immediately after validation passes

## 3. Cleanup Checklist (Part of QA)

Before marking a task complete (Step 11), verify:

- [ ] No `_chapter_*_raw.txt` files remain in `data/.agent_runtime/`
- [ ] No `_temp_*.json` files remain in `data/.agent_runtime/`
- [ ] No `_topic_research.json` remains after the completed history entry has been appended
- [ ] No `_editorial_message_lock.json` remains after the completed history entry has been appended
- [ ] No `_claim_evidence.json`, `_claim_evidence_content_receipt.json`, or `_topic_evidence_content_receipt.json` remains after the completed history entry has been appended
- [ ] No stale `_source_verification_cache.json` remains after the completed task when it is no longer needed
- [ ] No `_veo_progress_*.json` remains after the completed history entry has been appended
- [ ] No temporary files leaked into final output directories:
      - `data/video_short/[title-slug]/`
      - `data/video_long/[title-slug]/`
- [ ] Only the 4–5 required final files exist per video:
      - `master_script.txt`
      - `metadata.json`
      - `visual_bible.json`
      - `chapter_01.json` ... `chapter_[n].json`

This checklist is integrated into `07_qa_checklist.md §F3`.

## 4. Implementation Pattern

### Example: Multi-chapter processing with cleanup

```bash
# Step 1: Extract chapters to temp files
echo "Chapter 1 text..." > data/.agent_runtime/_chapter_01_raw.txt
echo "Chapter 2 text..." > data/.agent_runtime/_chapter_02_raw.txt

# Step 2: Process each chapter
python3 .agents/tools/word_splitter.py \
  --input data/.agent_runtime/_chapter_01_raw.txt \
  --type long --lang vi \
  --output data/video_long/sample-video/chapter_01.json

python3 .agents/tools/word_splitter.py \
  --input data/.agent_runtime/_chapter_02_raw.txt \
  --type long --lang vi \
  --scene-start 15 --sentence-start 8 \
  --output data/video_long/sample-video/chapter_02.json

# Step 3: Validate all chapters pass schema
python3 .agents/tools/schema_validator.py \
  --schema .agents/schemas/chapter.schema.json \
  --file data/video_long/sample-video/chapter_01.json

python3 .agents/tools/schema_validator.py \
  --schema .agents/schemas/chapter.schema.json \
  --file data/video_long/sample-video/chapter_02.json

# Step 4: CLEANUP - Delete temp files
rm data/.agent_runtime/_chapter_01_raw.txt
rm data/.agent_runtime/_chapter_02_raw.txt

# Now proceed to Step 8 (write veo_prompts)
```

### Example: History entry validation with cleanup

```bash
# Step 1: Create temp validation file
cat > data/.agent_runtime/_temp_history_entry.json << 'EOF'
{
  "id": "uuid-here",
  "title": "Video Title",
  ...
}
EOF

# Step 2: Validate
python3 .agents/tools/schema_validator.py \
  --schema .agents/schemas/history.schema.json \
  --file data/.agent_runtime/_temp_history_entry.json

# Step 3: If validation passes, append to history.json
# (use jq or Python to append the object to the array)

# Step 4: CLEANUP
rm data/.agent_runtime/_temp_history_entry.json
```

## 5. Why This Matters

**Code cleanliness:**
- Prevents git noise (temp files accidentally committed)
- Makes `data/` directory structure easy to understand
- Reduces confusion when debugging

**Reliability:**
- Old temp files won't interfere with new runs
- No risk of processing stale data
- Clear separation between work-in-progress and final output

**Professionalism:**
- Clean workspace = maintainable codebase
- Easier for humans to review agent work
- Follows software engineering best practices

## V9 semantic receipt lifecycle

**File pattern:** `_veo_semantic_receipts_<slug>.json`  
**Location:** `data/.agent_runtime/_veo_semantic_receipts_<slug>.json`

This file is a temporary, hash-bound proof that specific Veo micro-batches passed semantic QA. It is required while prompt production is in progress and through final QA. Do **not** delete it after each batch. Do **not** copy it into the final video folder.

Delete it only after:
1. all scenes are finished;
2. final `qa_automation.py` passes semantic-receipt coverage;
3. final `qa_automation.py` confirms all receipts use the current semantic ruleset and source hashes; and
4. the history entry/task completion write succeeds.

Do **not** run a redundant second full-video semantic AI review merely to satisfy cleanup.

Cleanup checklist addition:
- [ ] No `_veo_semantic_receipts_*.json` remains after successful final QA + history completion.


### Veo full-regeneration invalidation

A full `GenerateVeoPrompts` rerun invalidates every prior semantic receipt because the six-field Veo package is regenerated. `tools/veo_regeneration_prepare.py` deletes `_veo_progress_<slug>.json`, `_veo_semantic_receipts_<slug>.json`, and any derived `all_veo_prompt.json` before new prompt generation begins.

### V9 editorial semantic receipt

Keep `data/.agent_runtime/_editorial_semantic_receipt.json` together with `_editorial_message_lock.json` through final QA. It is runtime-only, hash-bound to the exact lock and `master_script.txt`, and must be regenerated after either changes. Delete it with the other runtime QA artifacts only after final QA/history persistence succeeds.
